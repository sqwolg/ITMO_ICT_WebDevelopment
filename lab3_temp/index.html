    Лабораторная работа №3

    Реализованный функционал

    1. Модели базы данных

    Реализованы модели для системы управления библиотекой с использованием Django ORM:

    • Author — авторы книг
    • ReadingHall — читальные залы библиотеки
    • Reader — читатели библиотеки
    • Book — книги
    • BookCopy — экземпляры книг в залах (связь многие-ко-многим через промежуточную модель)
    • BookAssignment — закрепления книг за читателями

    Все модели содержат необходимые поля согласно техническому заданию и используют связи ForeignKey и ManyToManyField с правильно настроенными related_name для удобных запросов.

    2. API на базе Django REST Framework

    Реализованы ViewSets для всех основных сущностей с поддержкой CRUD-операций:

    • AuthorViewSet — управление авторами
    • ReadingHallViewSet — управление читальными залами
    • ReaderViewSet — управление читателями
    • BookViewSet — управление книгами
    • BookCopyViewSet — управление экземплярами книг в залах
    • BookAssignmentViewSet — управление закреплениями книг

    Все ViewSets используют стандартные методы ModelViewSet (list, create, retrieve, update, destroy) и поддерживают пагинацию (20 элементов на страницу).

    3. Вложенные объекты для связей

    Реализованы дополнительные endpoints для получения вложенных объектов:

    Для связи один-ко-многим:

    • GET /api/reading-halls/<id>/readers/ — получить список читателей зала
    • GET /api/readers/<id>/books/ — получить список книг, закрепленных за читателем
    • GET /api/books/<id>/copies/ — получить список экземпляров книги в залах

    Для связи многие-ко-многим:

    • В сериализаторах реализованы вложенные объекты:
      • BookSerializer включает authors_detail (список авторов) и copies_detail (список экземпляров в залах)
      • ReaderSerializer включает reading_hall_detail (информация о зале)
      • BookAssignmentSerializer включает book_detail и reader_detail

    4. Аналитические запросы

    Реализован AnalyticsViewSet с аналитическими запросами согласно ТЗ:

    1. GET /api/analytics/reader_books/?reader_id=<id> — какие книги закреплены за заданным читателем?
      • Возвращает список активных закреплений книг за указанным читателем
    2. GET /api/analytics/old_assignments/ — кто из читателей взял книгу более месяца тому назад?
      • Находит всех читателей, у которых есть не возвращенные книги, закрепленные более 30 дней назад
    3. GET /api/analytics/readers_with_rare_books/ — за кем из читателей закреплены книги, количество экземпляров которых в библиотеке не превышает 2?
      • Использует агрегацию Django ORM (Sum) для подсчета общего количества экземпляров каждой книги
      • Находит читателей с закрепленными редкими книгами
    4. GET /api/analytics/young_readers_count/ — сколько в библиотеке читателей младше 20 лет?
      • Возвращает количество активных читателей, родившихся менее 20 лет назад
    5. GET /api/analytics/education_statistics/ — сколько читателей в процентном отношении имеют начальное образование, среднее, высшее, ученую степень?
      • Возвращает процентное соотношение читателей по уровням образования
      • Учитывает как поле education, так и has_degree

    5. Операции библиотекаря

    Реализован LibrarianOperationsViewSet с операциями для библиотекаря:

    1. POST /api/librarian-operations/register_reader/ — записать в библиотеку нового читателя
      • Принимает данные читателя через сериализатор
      • Автоматически устанавливает is_active=True
    2. POST /api/librarian-operations/exclude_old_readers/ — исключить из списка читателей людей, записавшихся в библиотеку более года назад и не прошедших перерегистрацию
      • Находит всех читателей, зарегистрированных более 365 дней назад
      • Устанавливает is_active=False для таких читателей
      • Возвращает количество исключенных читателей и их ID
    3. POST /api/librarian-operations/write_off_book/ — списать старую или потерянную книгу
      • Принимает book_id, reading_hall_id и quantity
      • Уменьшает количество экземпляров книги в указанном зале
      • Проверяет наличие достаточного количества экземпляров
    4. POST /api/librarian-operations/accept_book/ — принять книгу в фонд библиотеки
      • Принимает book_id, reading_hall_id и quantity
      • Создает новую запись BookCopy или увеличивает количество существующих экземпляров

    6. Отчеты

    Реализован ReportViewSet для генерации отчетов:

    GET /api/reports/monthly_report/?year=<year>&month=<month> — отчет о работе библиотеки в течение месяца

    Отчет включает:

    • Ежедневную статистику для каждого дня месяца:
      • Количество книг в библиотеке
      • Количество активных читателей
      • Количество читателей по каждому залу
    • Общую статистику за месяц:
      • Общее количество книг
      • Общее количество активных читателей
      • Количество новых читателей, записавшихся в отчетный месяц
      • Количество новых читателей по каждому залу

    7. Аутентификация и авторизация

    Реализована система аутентификации через Djoser с использованием токенов:

    • Регистрация пользователей: POST /api/auth/users/
    • Получение токена: POST /api/auth/token/login/
    • Выход (удаление токена): POST /api/auth/token/logout/
    • Информация о текущем пользователе: GET /api/auth/users/me/

    Все API endpoints требуют аутентификации (настроено через DEFAULT_PERMISSION_CLASSES в settings.py). Для доступа к API необходимо передавать токен в заголовке:

    Authorization: Token <your_token>

    8. Swagger документация

    Интегрирована документация API через drf-yasg:

    • Swagger UI: /swagger/ — интерактивная документация с возможностью тестирования API
    • ReDoc: /redoc/ — альтернативный формат документации

    Все endpoints документированы с помощью декораторов @swagger_auto_schema, включая описания параметров, типов ответов и примеры использования.

    Модели данных

    Author (Автор)

    Модель хранит информацию об авторах книг:

    • `name` — имя автора (CharField, max_length=200)
    • Связь ManyToMany с Book через поле `authors` в модели Book

    ReadingHall (Читальный зал)

    Модель хранит информацию о читальных залах:

    • `number` — номер зала (IntegerField, unique=True)
    • `name` — название зала (CharField, max_length=200)
    • `capacity` — вместимость зала (IntegerField, с валидатором MinValueValidator(1))
    • Связь один-ко-многим с Reader через `related_name='readers'`
    • Связь один-ко-многим с BookCopy через `related_name='book_copies'`

    Reader (Читатель)

    Модель хранит информацию о читателях библиотеки:

    • `ticket_number` — номер читательского билета (CharField, max_length=50, unique=True)
    • `full_name` — ФИО читателя (CharField, max_length=200)
    • `passport_number` — номер паспорта (CharField, max_length=50)
    • `birth_date` — дата рождения (DateField)
    • `address` — адрес (TextField)
    • `phone` — номер телефона (CharField, max_length=20)
    • `education` — образование (CharField, choices: 'primary', 'secondary', 'higher', 'degree')
    • `has_degree` — наличие ученой степени (BooleanField, default=False)
    • `reading_hall` — читальный зал (ForeignKey к ReadingHall, null=True, related_name='readers')
    • `registration_date` — дата регистрации (DateField, auto_now_add=True)
    • `is_active` — активен ли читатель (BooleanField, default=True)
    • Связь один-ко-многим с BookAssignment через `related_name='book_assignments'`

    Book (Книга)

    Модель хранит информацию о книгах:

    • `title` — название книги (CharField, max_length=300)
    • `authors` — авторы (ManyToManyField к Author, related_name='books')
    • `publisher` — издательство (CharField, max_length=200)
    • `publication_year` — год издания (IntegerField)
    • `section` — раздел (CharField, max_length=100)
    • `code` — шифр книги (CharField, max_length=100, unique=True)
    • `assignment_date` — дата закрепления за читателем (DateField, null=True, blank=True)
    • Связь один-ко-многим с BookCopy через `related_name='copies'`
    • Связь один-ко-многим с BookAssignment через `related_name='assignments'`

    BookCopy (Экземпляр книги в зале)

    Промежуточная модель для связи многие-ко-многим между Book и ReadingHall:

    • `book` — книга (ForeignKey к Book, related_name='copies')
    • `reading_hall` — читальный зал (ForeignKey к ReadingHall, related_name='book_copies')
    • `quantity` — количество экземпляров (IntegerField, с валидатором MinValueValidator(0), default=0)
    • Уникальное ограничение на пару (book, reading_hall) через `unique_together`

    BookAssignment (Закрепление книги за читателем)

    Модель хранит информацию о закреплении книг за читателями:

    • `book` — книга (ForeignKey к Book, related_name='assignments')
    • `reader` — читатель (ForeignKey к Reader, related_name='book_assignments')
    • `assignment_date` — дата закрепления (DateField, auto_now_add=True)
    • `is_returned` — возвращена ли книга (BooleanField, default=False)

    Сериализаторы

    AuthorSerializer

    Сериализатор для модели Author:

    • Поля: `id`, `name`, `books_count` (вычисляемое поле через `SerializerMethodField`)

    ReadingHallSerializer

    Сериализатор для модели ReadingHall:

    • Поля: `id`, `number`, `name`, `capacity`, `readers_count`, `books_count` (вычисляемые поля)

    ReaderSerializer

    Сериализатор для модели Reader:

    • Поля: все поля модели, `reading_hall_detail` (вложенный объект зала), `assigned_books_count` (количество закрепленных книг)
    • Использует `ReadingHallSerializer` для вложенного объекта зала

    BookSerializer

    Сериализатор для модели Book:

    • Поля: все поля модели, `authors_detail` (список авторов), `copies_detail` (список экземпляров в залах), `assignments_count` (количество активных закреплений)
    • Использует `AuthorSerializer` для списка авторов
    • Использует `BookCopyNestedSerializer` для списка экземпляров

    BookCopySerializer

    Сериализатор для модели BookCopy:

    • Поля: `id`, `book`, `book_detail` (вложенный объект книги), `reading_hall`, `reading_hall_detail` (вложенный объект зала), `quantity`
    • Использует `BookSerializer` и `ReadingHallSerializer` для вложенных объектов

    BookAssignmentSerializer

    Сериализатор для модели BookAssignment:

    • Поля: `id`, `book`, `book_detail` (вложенный объект книги), `reader`, `reader_detail` (вложенный объект читателя), `assignment_date`, `is_returned`
    • Использует `BookSerializer` и `ReaderSerializer` для вложенных объектов

    Использование related_name

    В проекте правильно настроены related_name для всех связей:

    1. **ReadingHall.readers** — обратный доступ к читателям зала через `hall.readers.all()`
    2. **ReadingHall.book_copies** — обратный доступ к экземплярам книг через `hall.book_copies.all()`
    3. **Reader.book_assignments** — обратный доступ к закреплениям через `reader.book_assignments.all()`
    4. **Book.copies** — обратный доступ к экземплярам через `book.copies.all()`
    5. **Book.assignments** — обратный доступ к закреплениям через `book.assignments.all()`
    6. **Author.books** — обратный доступ к книгам через `author.books.all()`

    Примеры использования в коде:

    • `hall.readers.filter(is_active=True)` — активные читатели зала
    • `reader.book_assignments.filter(is_returned=False)` — активные закрепления читателя
    • `book.copies.all()` — все экземпляры книги в залах
    • `author.books.count()` — количество книг автора

    Работа с ManyToMany связями

    Связь Book ↔ Author (ManyToMany)

    • Реализована через стандартное поле `ManyToManyField`
    • В сериализаторе `BookSerializer` используется `authors_detail` для получения вложенных объектов авторов
    • В сериализаторе `AuthorSerializer` вычисляется `books_count` через `obj.books.count()`

    Связь Book ↔ ReadingHall (ManyToMany через промежуточную модель)

    • Реализована через промежуточную модель `BookCopy`
    • Позволяет хранить дополнительную информацию (количество экземпляров) для каждой пары книга-зал
    • В сериализаторе `BookSerializer` используется `copies_detail` для получения списка экземпляров с информацией о залах
    • В сериализаторе `ReadingHallSerializer` вычисляется `books_count` через `obj.book_copies.filter(quantity__gt=0).count()`

    Админ-панель Django

    Все модели зарегистрированы в админ-панели с настройками:

    AuthorAdmin

    • Отображение: `name`
    • Поиск: по имени

    ReadingHallAdmin

    • Отображение: `number`, `name`, `capacity`
    • Поиск: по названию и номеру

    ReaderAdmin

    • Отображение: `ticket_number`, `full_name`, `reading_hall`, `education`, `is_active`
    • Фильтры: по образованию, наличию степени, активности, залу
    • Поиск: по номеру билета, ФИО, номеру паспорта

    BookAdmin

    • Отображение: `code`, `title`, `publisher`, `publication_year`, `section`
    • Фильтры: по разделу и году издания
    • Поиск: по названию, шифру, издательству
    • Горизонтальный фильтр для выбора авторов (`filter_horizontal`)

    BookCopyAdmin

    • Отображение: `book`, `reading_hall`, `quantity`
    • Фильтры: по залу
    • Поиск: по названию и шифру книги

    BookAssignmentAdmin

    • Отображение: `book`, `reader`, `assignment_date`, `is_returned`
    • Фильтры: по статусу возврата и дате закрепления
    • Поиск: по названию книги, ФИО и номеру билета читателя

    Заключение

    В ходе выполнения лабораторной работы была реализована полнофункциональная система управления библиотекой с использованием Django REST Framework:

    1. **Модели данных** — спроектированы с учетом нормализации и правильного использования связей (ForeignKey, ManyToMany) с настроенными `related_name`
