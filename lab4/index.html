    Лабораторная работа №4

    Реализованный функционал

    1. Настройка CORS для серверной части

    Настроен CORS (Cross-Origin Resource Sharing) для обеспечения взаимодействия между клиентской частью (Vue.js) и серверной частью (Django REST Framework).

    2. Определение минимального списка интерфейсов

    Определены и реализованы следующие интерфейсы для взаимодействия с серверной частью:

    Интерфейсы аутентификации:

    • Регистрация пользователя — создание нового аккаунта
    • Авторизация — вход в систему с получением токена
    • Просмотр профиля — информация о текущем пользователе
    • Обновление профиля — изменение данных пользователя
    • Смена пароля — изменение пароля пользователя
    • Выход — завершение сессии

    Интерфейсы для работы с данными:

    • Книги — просмотр списка книг с информацией об авторах
    • Читатели — просмотр списка читателей с информацией о залах
    • Читальные залы — просмотр списка залов с статистикой

    3. Реализация интерфейсов авторизации, регистрации и изменения учётных данных

    3.1. Компонент регистрации (Register.vue)

    Реализован интерфейс регистрации нового пользователя: - Поля формы: имя пользователя, пароль, подтверждение пароля - Валидация совпадения паролей на клиенте - Отправка данных на /api/auth/users/ через Djoser - Обработка ошибок регистрации - Перенаправление на страницу входа после успешной регистрации

    Используемые API endpoints: - POST /api/auth/users/ — создание пользователя

    3.2. Компонент авторизации (Login.vue)

    Реализован интерфейс входа в систему: - Поля формы: имя пользователя, пароль - Отправка данных на /api/auth/token/login/ для получения токена - Сохранение токена в localStorage - Получение информации о пользователе через /api/auth/users/me/ - Сохранение данных пользователя в localStorage - Обработка ошибок авторизации - Перенаправление на главную страницу после успешного входа

    Используемые API endpoints: - POST /api/auth/token/login/ — получение токена авторизации - GET /api/auth/users/me/ — информация о текущем пользователе

    3.3. Компонент профиля (Profile.vue)

    Реализован интерфейс управления профилем пользователя с двумя вкладками:

    Вкладка "Профиль": - Отображение текущих данных пользователя (username, email, first_name, last_name) - Форма для обновления данных профиля - Отправка данных на /api/auth/users/me/ методом PATCH - Отображение сообщений об успехе/ошибке

    Вкладка "Смена пароля": - Поля формы: текущий пароль, новый пароль, подтверждение нового пароля - Валидация совпадения паролей на клиенте - Отправка данных на /api/auth/users/set_password/ - Отображение сообщений об успехе/ошибке - Очистка формы после успешной смены пароля

    Используемые API endpoints: - GET /api/auth/users/me/ — получение данных пользователя (через store) - PATCH /api/auth/users/me/ — обновление данных профиля - POST /api/auth/users/set_password/ — смена пароля

    4. Реализация клиентских интерфейсов для работы с данными

    4.1. Компонент списка книг (Books.vue)

    Реализован интерфейс для просмотра списка книг: - Таблица с использованием компонента v-data-table из Vuetify - Отображение колонок: ID, название, авторы, издательство, год издания, раздел, шифр - Обработка вложенных объектов авторов (authors_detail) с отображением списка авторов через запятую - Поддержка пагинации (если сервер возвращает пагинированные данные) - Индикатор загрузки данных - Обработка ошибок загрузки

    Используемые API endpoints: - GET /api/books/ — получение списка книг

    4.2. Компонент списка читателей (Readers.vue)

    Реализован интерфейс для просмотра списка читателей: - Таблица с использованием компонента v-data-table из Vuetify - Отображение колонок: ID, номер билета, ФИО, паспорт, дата рождения, образование, читальный зал - Обработка вложенных объектов зала (reading_hall_detail) с отображением названия зала - Преобразование кодов образования в читаемые названия (primary → Начальное, secondary → Среднее, и т.д.) - Поддержка пагинации - Индикатор загрузки данных - Обработка ошибок загрузки

    Используемые API endpoints: - GET /api/readers/ — получение списка читателей

    4.3. Компонент списка читальных залов (ReadingHalls.vue)

    Реализован интерфейс для просмотра списка читальных залов: - Таблица с использованием компонента v-data-table из Vuetify - Отображение колонок: ID, номер, название, вместимость, количество читателей, количество книг - Отображение вычисляемых полей из сериализатора (readers_count, books_count) - Поддержка пагинации - Индикатор загрузки данных - Обработка ошибок загрузки

    Используемые API endpoints: - GET /api/reading-halls/ — получение списка читальных залов

    5. Подключение Vuetify

    Подключена библиотека Vuetify для создания современного Material Design интерфейса.

    Установка зависимостей:

    npm install vuetify@^3.4.7 @mdi/font

    Настройка в src/plugins/vuetify.js: - Импорт всех компонентов и директив Vuetify - Импорт стилей Vuetify - Импорт иконок Material Design Icons - Настройка темы (светлая тема по умолчанию)

    Подключение в src/main.js: - Создание экземпляра Vuetify - Регистрация плагина в приложении Vue

    Использование компонентов Vuetify: - v-app — корневой компонент приложения - v-app-bar — панель навигации - v-container, v-row, v-col — система сетки - v-card, v-card-title, v-card-text — карточки - v-data-table — таблицы данных - v-form — формы - v-text-field — текстовые поля - v-btn — кнопки - v-alert — уведомления - v-tabs, v-tab, v-window, v-window-item — вкладки - v-divider — разделители

    Архитектура клиентского приложения

    Сервис API (src/services/api.js)

    Реализован централизованный сервис для работы с API:

    1. Создание экземпляра Axios:
    2. Базовый URL: http://localhost:8000/api

    3. Заголовок Content-Type: application/json по умолчанию

    4. Request interceptor:

    5. Автоматическое добавление токена авторизации к каждому запросу
    6. Формат заголовка: Authorization: Token <token>

    7. Получение токена из Pinia store

    8. Response interceptor:

    9. Обработка ошибок авторизации (401)
    10. Автоматический выход пользователя при истечении токена
    11. Перенаправление на страницу входа при ошибке 401

    Store аутентификации (src/stores/auth.js)

    Реализован Pinia store для управления состоянием аутентификации:

    Состояние (state): - token — токен авторизации (хранится в localStorage) - user — данные текущего пользователя (хранится в localStorage)

    Вычисляемые свойства (computed): - isAuthenticated — проверка наличия токена

    Методы (actions): - login(username, password) — вход в систему - Получение токена через /api/auth/token/login/ - Сохранение токена в localStorage - Получение данных пользователя через /api/auth/users/me/ - Сохранение данных пользователя в localStorage - Возврат результата с обработкой ошибок

    • register(username, password, passwordConfirm) — регистрация
    • Создание пользователя через /api/auth/users/

    • Возврат результата с обработкой ошибок

    • updateProfile(data) — обновление профиля

    • Отправка PATCH запроса на /api/auth/users/me/
    • Обновление данных пользователя в store и localStorage

    • Возврат результата с обработкой ошибок

    • changePassword(currentPassword, newPassword) — смена пароля

    • Отправка POST запроса на /api/auth/users/set_password/

    • Возврат результата с обработкой ошибок

    • logout() — выход из системы

    • Очистка токена и данных пользователя
    • Удаление данных из localStorage

    Маршрутизация (src/router/index.js)

    Настроена маршрутизация с защитой маршрутов:

    Маршруты: - / — редирект на /books - /login — страница входа (не требует авторизации) - /register — страница регистрации (не требует авторизации) - /profile — страница профиля (требует авторизации) - /books — страница списка книг (требует авторизации) - /readers — страница списка читателей (требует авторизации) - /reading-halls — страница списка залов (требует авторизации)

    Навигационный guard (beforeEach): - Проверка требования авторизации для защищенных маршрутов - Перенаправление на /login для неавторизованных пользователей - Перенаправление на / для авторизованных пользователей, пытающихся зайти на /login или /register

    Главный компонент (App.vue)

    Реализован корневой компонент приложения:

    • Условное отображение панели навигации — только для авторизованных пользователей
    • Навигационное меню с кнопками:
    • Книги
    • Читатели
    • Читальные залы
    • Профиль
    • Выход
    • Обработка выхода — вызов метода logout из store и перенаправление на страницу входа
    • Router view — отображение компонентов страниц
